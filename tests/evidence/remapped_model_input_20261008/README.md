# Normal remapped Model input: one bounded import PASS

This development control reuses the author-owned FBX and three Material assets from the original `tests/unity_model_material_probe/fixtures/ThreeSlotSource.unitypackage` (SHA256 `d6245d25c3cbd513c49b8d2e241b313a752331cd338563becab6eb7c819bfa0c`). It does not repair or replace that package. Only FBX/Material payloads and metas are copied into a fresh owned Unity 2022.3.22f1 project; no Prefab or override is included.

The author explicitly maps the three actual embedded Material identifiers `Public fixture material 0/1/2` to the existing Material GUIDs through standard ModelImporter.AddRemap, saves/reimports, and uses normal AssetDatabase.ExportPackage with IncludeDependencies. These are declared author mappings, not inference from names, slot indices or face counts. The package contains the resulting ordinary ModelImporter remaps; no VAPB correspondence manifest or development oracle is inserted. The copied importer settings are restored after package generation. All eight staged original FBX/Material/meta files, the original archive and original dirty6 retain their hashes.

The generated normal input SHA256 is `3f0612d120949d692883cd318b7d5f72a358b9105e77e54b5368dd9e3ffde65b`. FBX payload SHA256 remains `fbe25a43a81a066c443093a0788a05569a4ec54e2d673fe133bffa7f801309c5`. Unity observes all three exact external Material GUID/fileID references on the imported model; its submesh order differs from Blender. Submesh counts are recorded for context and do not select the correspondence.

Factory/background Blender 5.2.1 imports that exact package through the normal production `bpy.ops.import_scene.unitypackage` operator. No model witness, Confirm, identity injection, face reassignment, scene save or export is used. The observation independently reads raw FBX Geometry polygon corners, LayerElementMaterial and Material-to-Model connections, joins their actual source identifiers through the package's explicit remaps, and compares this labelled triangle multiset with the imported Blender mesh and effective Material GUID/fileID/package identities. All 12 triangles and duplicate multiplicities match at six-decimal quantization in raw FBX geometry-local versus Blender mesh-local coordinates, without a fitted transform. Winding is not asserted. Normal dependency resolution reports local=3, unresolved=0, ambiguous=0.

Unity and Blender each ran once and exited normally with OS code 0. Postflight confirmed no owned processes/children and no Unity Project lock. Unity slot returned. The measurement scripts and sanitized observations are retained; generated package, source assets, absolute paths and raw logs remain local.

This proves that explicit ordinary ModelImporter remaps can provide sufficient inbound identity information for this no-Prefab Model case using the existing product path. It does not prove arbitrary import policies, duplicate/renamed source identifiers, skin/winding/normal fidelity, Texture closure, export/Unity return, Prefab overrides or full product acceptance. The original ThreeSlot Prefab case remains partial/unresolved with its old failures preserved. Users are not required to create remaps or perform Unity preprocessing; this is one developer-owned control, not a new normal-input requirement. No product source fix was needed for this case.
