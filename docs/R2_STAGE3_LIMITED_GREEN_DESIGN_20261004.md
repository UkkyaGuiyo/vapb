## Approved contract and correction

`PRODUCT_SPEC.md` lines 30–37 makes Blender's exported final mesh authoritative for geometry, topology, UV, bones/weights, Shape Keys, material-slot structure and face-to-slot assignment. It says source geometry lineage is not normally required, permits deleting imported meshes and creating new meshes, and defines the Finalizer as reconnecting preserved Unity semantics rather than retaining source Mesh local IDs. `docs/VAPB_BOUNDED_SKIN_ROUNDTRIP_ACCEPTANCE_20261001.md` lines 113–115 likewise says its preserved-source fixture does not impose source Mesh lineage on ordinary Blender-final-state exports or geometry replacement.

Therefore the current `Kind` index/count rejection is implementation behavior, not an approved source-geometry identity contract. The prior design claim that lineage is a mandatory GREEN blocker is withdrawn. Do not add lineage transport/schema/importer support, and do not compare source and final face/vertex/weight correspondence as a general product requirement. The RED case's source/final geometry comparison is a fixture-specific test oracle only.

## Current code path and bounded objective

`VapbModelSkinFinalizer.Apply` validates and prepares tasks, refreshes the edited FBX, resolves the original source Prefab occurrence and the exported Blender Mesh/bones/materials, calls `CheckSkinCompatibility`, and saves a Variant through `SaveVariant`. `SaveVariant` instantiates the source Prefab as the Variant parent and assigns `plan.edited.mesh` directly to the target renderer. `VerifyVariant` checks exact Mesh/bone/material bindings, source hierarchy and absence of added/removed objects/components. The legacy normal-Kind branch is selected when vertex count, submesh topology and each index array match the witnessed source; it retains the prior `SameBlendShapes`, multi-task, multi-renderer and ordinary Prefab behavior. Any changed index layout selects the strict synthetic replacement branch. That branch does not silently expand acceptance to mixed/multiple tasks, shape-bearing meshes or unreviewed Avatar components.

`CheckSkinCompatibility` routes exact same vertex-count/submesh-topology/index-array normal-Kind inputs through the legacy branch, retaining prior `SameBlendShapes` behavior. Changed index layout alone enters the strict synthetic replacement branch; source-vertex lineage is not required for the final Blender-authored Mesh.

Initial supported eligibility for the changed-index-layout synthetic route is triangle-submesh skinned Meshes with zero Shape Keys on both source and final Mesh, a single authorized target renderer, resolvable final material transport, and a minimal source Prefab with no Cloth, missing scripts or unapproved/unknown components. These limits apply only when vertex count, submesh topology or an index array changes. Preserve the pre-existing normal-Kind path for exact same-index-layout meshes, including its prior Shape Key, multi-task, multi-SkinnedMeshRenderer and ordinary Prefab acceptance behavior. These conservative limits are not limits on the product's Blender-final-Mesh authority. The 4-to-6 vertex, two-triangle seam split is only the reviewed synthetic fixture; do not hardcode vertex count, triangle count, seam count or source/final face equality in product policy.

## Limited whole-final-Mesh replacement contract

- **Authority:** use the exact Unity-imported Blender final `Mesh` as the Variant renderer's `sharedMesh`. No source geometry/index equality test; no Unity-side geometry reconstruction. Do not mutate source FBX, source Prefab, manifest or their metadata.
- **Mesh safety:** validate the complete final Mesh before creating any Variant: nonempty vertices; all supported vertex streams finite and either absent or exactly vertex-count sized; enumerate `Mesh.GetVertexAttributes` and allow only the explicitly supported Position/Normal/Tangent/Color/TexCoord0–7/BlendWeight/BlendIndices set; reject unrecognized attributes; finite bounds; supported triangle topology only in this initial scope; every submesh has triangle topology; `SubMeshDescriptor.indexStart/indexCount` lie inside the mesh index buffer; `indexCount` is divisible by three; every effective index after `baseVertex` is in range. Final stream values, faces and vertex count are authoritative, not required to match source values.
- **Skin safety:** validate all final vertex weights as nonempty, finite, positive, normalized influences within the final bone array; validate bone-index ranges and exact bone UID bijection; preserve the source target root and bone parent identity; require each final bindpose to match the mapped source bone rest relation using the current finite/tolerance checks. Final weights are authoritative, so do not require source per-vertex weights to match.
- **Shape initial scope:** require zero Shape Keys on the source target Mesh and zero on the final Mesh. Unity exposes effective per-shape weights by index only when the renderer Mesh has shapes; if both Meshes have zero shapes, there is no effective blendShapeWeight slot to preserve or reinterpret. Do not claim inspection of an inaccessible stale serialized array. Verify the Variant has zero final shapes and no blendShapeWeight override. Supporting any Shape Keys remains a later explicit contract; source-to-final shape-delta lineage is not implied.
- **Material safety:** require explicit final material transport identities; resolve each imported carrier to its exact preserved Unity Material GUID/fileID; require carrier count to equal final submesh count, no missing/ambiguous/unused declarations. Final submesh-to-material assignment is Blender-authored authority; source face-to-slot continuity is not asserted.
- **Index-dependent Unity state:** reject Cloth when replacing the target mesh. For this minimal synthetic Prefab route, scan the complete source Prefab hierarchy and fail closed on missing scripts, extra Renderers/colliders, arbitrary MonoBehaviours and unknown components; permit only `Transform`, the single target `SkinnedMeshRenderer`, required bone transforms, and a specifically reviewed VAPB marker if present. This deliberately excludes ordinary Avatar/custom-component coverage; it is a conservative eligibility limit, not a claim that all those components are index-dependent. No source vertex-indexed state is remapped. Broader component support needs per-component preservation proof or a separate remap contract.
- **Remaining renderer state and bounds frame (changed-layout route only):** capture and verify the target renderer's effective `localBounds` center/extents unchanged, finite, and nonnegative. Unity 2022.3.22f1 measurements on this synthetic imported rig showed that transforming `localBounds` corners through `rootBone` reproduced the actual `Renderer.bounds`; transforming them through the renderer Transform did not. Therefore do not compare raw Mesh vertices/AABB or edited renderer Transform corners directly to target `localBounds`. Validate the final Mesh AABB against its own raw vertices separately. For bounds eligibility, cache each final bindpose and compose `target.rootBone.worldToLocalMatrix * mappedTargetBone.localToWorldMatrix * bindpose` once per bone slot. Apply those root-frame skin matrices to every final Mesh vertex, weighted-sum the resulting rootBone-local influence points, and require each point to lie inside the preserved target `localBounds` with at most `0.001` rootBone-local units of absolute tolerance per axis. Reject a null, non-finite, non-invertible or non-round-tripping rootBone transform. This avoids a weight-sum translation error from first summing in world space and then applying one root inverse. The 0.001 value is a fixture-scale proposal, not a margin measured by the RED evidence; with the fixture's approximately 100x scale it corresponds to about 0.1 world units. Keep the `rootBone` reference and exact `localBounds` unchanged. This is a current/rest-pose containment check; it makes no claim that all animation poses are enclosed or that arbitrary frustum-culling behavior is safe. The independent test oracle uses Unity `BakeMesh(true)`, transforms baked vertices renderer-local-to-world and world-to-rootBone-local, checks containment, and compares root-frame AABB extrema with the explicit skin-equation result; it does not assert pointwise source/final vertex parity. Verify named effective properties `enabled`, `shadowCastingMode`, `receiveShadows`, `rootBone`, `bones`, `sharedMaterials`, `sharedMesh`, and `localBounds`; do not claim byte equality for all Renderer state. Same-index-layout legacy normal-Kind tasks do not receive these new predicates. In the zero-shape changed-layout scope, verify zero final shapes and no Variant blendShapeWeight override; stale inaccessible serialized arrays are not a claimed check.
- **Fixture evidence summary (Unity 2022.3.22f1; synthetic rig only):** the read-only Source/edited/Prefab probe recorded three rows with no probe errors. Target `localBounds` min/max were approximately `(-0.01, 0, -0.01)` / `(0.01, 0, 0.01)`; the target renderer Transform and rootBone each had scale about 100, with the renderer frame rotated about 90 degrees relative to the rootBone. Transforming the eight bounds corners by the renderer Transform yielded a world Y extent about `[-1, 1]` and near-zero Z; transforming by rootBone yielded world bounds approximately `(-1, 0, -1)` to `(1, 0, 1)`, matching the measured target `Renderer.bounds` within floating-point noise. Explicit weighted skin points were also approximately those world extrema. The raw Mesh bounds remained approximately `[-0.01, 0.01]` in its XY plane. This observation explains why the previous renderer-frame bounds comparison rejected the fixture; it is not a general guarantee for every Unity version, rig, bindpose convention, or animation state. The older V6 Apply probe separately recorded `TARGET_LOCAL_BOUNDS_INSUFFICIENT`, did not apply the finalizer, and created no Variant; it predates the rootBone-frame implementation and is not a result for the current diff. The latest V7 implementation/probe has not yet been compiled or run in Unity. Regression candidates: preserve shape-bearing exact same-index-layout normal-Kind acceptance and multi-task/multi-SkinnedMeshRenderer behavior; reject changed index layout with shapes or with more than one task; independently check changed-layout rest-pose bounds against `BakeMesh(true)`; exercise null/singular/non-finite rootBone inputs and all six bounds faces at the rootBone-local 0.001 tolerance boundary; separately record animation-pose containment as unresolved.

## VRChat use and verification boundary

VAPB's user entry point is the `.unitypackage` imported directly into Blender for VRChat Avatar modification; the user workflow must not require creating/importing into a Unity Project or manually exporting FBX first. A disposable Unity Project and Unity Editor may be used as development/test oracles for package import, finalization and round-trip checks, but those are verification steps, not product-user prerequisites. A World-only interpretation of this geometry fixture is insufficient for product completion. The user-required editor baseline remains Unity `2022.3.22f1`; do not change to Unity 6. The current disposable Stage 3 Target manifest contains only `com.unity.test-framework` `1.1.33` and has no VRChat SDK package, so no SDK was installed or changed for this checkpoint. The project specification calls out Avatar Descriptor, Animator/Expressions, PhysBone/Collider, Contact, supported Constraints, Unity Materials/Textures and related Unity/VRC state as preservation targets. The changed-layout synthetic allowlist deliberately refuses such extra Avatar components; it is a narrow safety gate, not VRC Avatar compatibility evidence and not a substitute for the existing same-index-layout route.

Before describing VAPB as end-to-end verified for VRChat, use the SDK package already authorized and used by the intended Avatar project (record the exact SDK package/type and version from that project; none is declared in this synthetic Target), in a newly approved disposable verification copy only. Verify a self-contained exported package import and Finalizer round-trip for the supported Avatar Descriptor, Animator/Expression references, PhysBone/Collider/Contact/Constraint state and relevant renderer/material bindings, plus upload validation if separately authorized. This checkpoint does not add dependencies, modify SDK/license/security settings, or perform an upload. Preserve the distinction between this Unity synthetic geometry test and Avatar/VRC semantic restoration coverage.
- **Prefab semantics:** keep the original source Prefab as the Variant parent; preserve its GUID, bytes, `.meta`, hierarchy, transforms, components and non-target renderer/material references. Variant modifications are limited to the authorized target's `m_Mesh`, `m_Bones`, and `m_Materials` bindings (plus already tolerated Unity root defaults). Verify the saved/reloaded Variant references the exact imported final Mesh.
- **Atomic rejection and idempotence:** run every task and safety check before writing a Variant. Invalid input leaves no Variant and leaves source Prefab/model/manifest bytes, `.meta`, GUID/local IDs and non-target semantic state unchanged. Repeated successful Apply yields the same Variant and exact final Mesh binding without accumulating overrides/assets.
- **DirectKind:** keep `RESTORE_DIRECT_SKIN_VARIANT_V1` behavior and its existing tests unchanged. Do not broaden or repurpose its compatibility branch to implement normal `Kind` policy.

## SOL review and remaining review gate

SOL reviewed the finalizer, RED evidence, `PRODUCT_SPEC.md` lines 30–37, bounded acceptance lines 113–115, and this corrected design. The current RED's geometry-equality result remains a test oracle for that fixture and is not a general finalizer policy.
