## Approved contract and correction

`PRODUCT_SPEC.md` lines 30–37 makes Blender's exported final mesh authoritative for geometry, topology, UV, bones/weights, Shape Keys, material-slot structure and face-to-slot assignment. It says source geometry lineage is not normally required, permits deleting imported meshes and creating new meshes, and defines the Finalizer as reconnecting preserved Unity semantics rather than retaining source Mesh local IDs. `docs/VAPB_BOUNDED_SKIN_ROUNDTRIP_ACCEPTANCE_20261001.md` lines 113–115 likewise says its preserved-source fixture does not impose source Mesh lineage on ordinary Blender-final-state exports or geometry replacement.

Therefore the current `Kind` index/count rejection is implementation behavior, not an approved source-geometry identity contract. The prior design claim that lineage is a mandatory GREEN blocker is withdrawn. Do not add lineage transport/schema/importer support, and do not compare source and final face/vertex/weight correspondence as a general product requirement. The RED case's source/final geometry comparison is a fixture-specific test oracle only.

## Current code path and bounded objective

`VapbModelSkinFinalizer.Apply` validates and prepares tasks, refreshes the edited FBX, resolves the original source Prefab occurrence and the exported Blender Mesh/bones/materials, calls `CheckSkinCompatibility`, and saves a Variant through `SaveVariant`. `SaveVariant` instantiates the source Prefab as the Variant parent and assigns `plan.edited.mesh` directly to the target renderer. `VerifyVariant` checks exact Mesh/bone/material bindings, source hierarchy and absence of added/removed objects/components.

`CheckSkinCompatibility` currently rejects normal `Kind` vertex-count and index changes before `ValidateMeshStreams` is called; the direct branch has a separate changed-layout path. A safe Kind change may admit an edited whole Mesh without source vertex lineage while preserving source Prefab identity and Unity-side semantics. Its claim is: “the validated Blender-authored final Mesh is assigned as exported.” It does not claim source geometry or source per-face semantics survived editing.

Initial supported eligibility for this synthetic route is triangle-submesh skinned Meshes with zero Shape Keys on both source and final Mesh, a single authorized target renderer, resolvable final material transport, and a minimal source Prefab with no Cloth, missing scripts or unapproved/unknown components. These are conservative limits of this test path, not limits on the product's Blender-final-Mesh authority. The 4-to-6 vertex, two-triangle seam split is only the reviewed synthetic fixture; do not hardcode vertex count, triangle count, seam count or source/final face equality in product policy.

## Limited whole-final-Mesh replacement contract

- **Authority:** use the exact Unity-imported Blender final `Mesh` as the Variant renderer's `sharedMesh`. No source geometry/index equality test; no Unity-side geometry reconstruction. Do not mutate source FBX, source Prefab, manifest or their metadata.
- **Mesh safety:** validate the complete final Mesh before creating any Variant: nonempty vertices; all supported vertex streams finite and either absent or exactly vertex-count sized; enumerate `Mesh.GetVertexAttributes` and allow only the explicitly supported Position/Normal/Tangent/Color/TexCoord0–7/BlendWeight/BlendIndices set; reject unrecognized attributes; finite bounds; supported triangle topology only in this initial scope; every submesh has triangle topology; `SubMeshDescriptor.indexStart/indexCount` lie inside the mesh index buffer; `indexCount` is divisible by three; every effective index after `baseVertex` is in range. Final stream values, faces and vertex count are authoritative, not required to match source values.
- **Skin safety:** validate all final vertex weights as nonempty, finite, positive, normalized influences within the final bone array; validate bone-index ranges and exact bone UID bijection; preserve the source target root and bone parent identity; require each final bindpose to match the mapped source bone rest relation using the current finite/tolerance checks. Final weights are authoritative, so do not require source per-vertex weights to match.
- **Shape initial scope:** require zero Shape Keys on the source target Mesh and zero on the final Mesh. Unity exposes effective per-shape weights by index only when the renderer Mesh has shapes; if both Meshes have zero shapes, there is no effective blendShapeWeight slot to preserve or reinterpret. Do not claim inspection of an inaccessible stale serialized array. Verify the Variant has zero final shapes and no blendShapeWeight override. Supporting any Shape Keys remains a later explicit contract; source-to-final shape-delta lineage is not implied.
- **Material safety:** require explicit final material transport identities; resolve each imported carrier to its exact preserved Unity Material GUID/fileID; require carrier count to equal final submesh count, no missing/ambiguous/unused declarations. Final submesh-to-material assignment is Blender-authored authority; source face-to-slot continuity is not asserted.
- **Index-dependent Unity state:** reject Cloth when replacing the target mesh. For this minimal synthetic Prefab route, scan the complete source Prefab hierarchy and fail closed on missing scripts, extra Renderers/colliders, arbitrary MonoBehaviours and unknown components; permit only `Transform`, the single target `SkinnedMeshRenderer`, required bone transforms, and a specifically reviewed VAPB marker if present. This deliberately excludes ordinary Avatar/custom-component coverage; it is a conservative eligibility limit, not a claim that all those components are index-dependent. No source vertex-indexed state is remapped. Broader component support needs per-component preservation proof or a separate remap contract.
- **Remaining renderer state:** capture and verify the target renderer's effective `localBounds` center/extents unchanged, finite, and nonnegative. For this fixture, transform all eight corners of the imported final Mesh-local bounds through the owning edited `SkinnedMeshRenderer` transform and world space into target-renderer local space, and require containment in the preserved `localBounds`, allowing at most `0.001` Unity units of float tolerance per axis. This is a proposed fixture-scale absolute tolerance, not a margin measured by the RED evidence. Test exact containment, the tolerance boundary, and rejection just outside it. This checks the undeformed imported Mesh AABB under rest-coordinate transforms only; it does not evaluate skinned/deformed extrema and makes no animation or general frustum-culling safety claim. Verify named effective properties `enabled`, `shadowCastingMode`, `receiveShadows`, `rootBone`, `bones`, `sharedMaterials`, `sharedMesh`, and `localBounds`; do not claim byte equality for all Renderer state. In the zero-shape scope, verify zero final shapes and no Variant blendShapeWeight override; stale inaccessible serialized arrays are not a claimed check.
- **Prefab semantics:** keep the original source Prefab as the Variant parent; preserve its GUID, bytes, `.meta`, hierarchy, transforms, components and non-target renderer/material references. Variant modifications are limited to the authorized target's `m_Mesh`, `m_Bones`, and `m_Materials` bindings (plus already tolerated Unity root defaults). Verify the saved/reloaded Variant references the exact imported final Mesh.
- **Atomic rejection and idempotence:** run every task and safety check before writing a Variant. Invalid input leaves no Variant and leaves source Prefab/model/manifest bytes, `.meta`, GUID/local IDs and non-target semantic state unchanged. Repeated successful Apply yields the same Variant and exact final Mesh binding without accumulating overrides/assets.
- **DirectKind:** keep `RESTORE_DIRECT_SKIN_VARIANT_V1` behavior and its existing tests unchanged. Do not broaden or repurpose its compatibility branch to implement normal `Kind` policy.

## Proposed code/test-first surface (not changed in this checkpoint)

1. **Tests first:** add an Editor integration regression for the existing synthetic RED package. Under the approved final-Mesh-authority policy it becomes a candidate positive: the saved Variant must reference the exact imported final Mesh and satisfy all safety/preservation checks. Keep its 4→6 and source/final face/weight comparisons in the fixture oracle only; they must not become generic finalizer predicates.
2. **Positive assertions:** check complete final streams and valid indices/weights, bone UID/root/parent/rest/bindpose mapping, final material identity/cardinality, zero shapes and no shape-weight override, source localBounds effective-value equality plus transformed rest-Mesh containment, named renderer property values, source Prefab bytes/GUID/local IDs/hierarchy/components and non-target semantics, Variant parent/type/reload, exact `sharedMesh`, only permitted overrides, and repeated Apply idempotence.
3. **Negative controls:** malformed/nonfinite/wrong-sized/unrecognized streams; unsupported topology; empty mesh; invalid submesh descriptor/index ranges; negative/out-of-range/malformed indices; missing/zero/nonfinite/unnormalized weights or invalid bone index; duplicate/missing/unknown bone UID, wrong root/parent/rest/bindpose; missing/ambiguous material ID or carrier/submesh cardinality error; any source/final Shape Key in this zero-shape initial scope; Cloth; unknown component, extra renderer/collider or missing script; nonfinite/negative/insufficient localBounds. Each must reject before Variant save and preserve source hashes/identities.
4. **Functions to change only after RED tests:** `CheckSkinCompatibility` should keep the `DirectKind` branch intact and give normal `Kind` its own replacement validator that no longer demands source count/index equality, requires zero shapes, and invokes complete stream/attribute/submesh/index/weight validation while retaining bone UID/rest checks. Add a preflight helper called before `SaveVariant` to enforce the synthetic component allowlist, shape, material and renderer-state gates. Capture the target renderer's localBounds and named semantic property values in `PreparedTask`; extend `VerifyVariant` to assert effective values in the reloaded Variant and its final Mesh, without permitting extra overrides. `ResolveEdited`/`ResolveMaterialTransport` remain responsible for final Bone IDs and Material transport; require explicit bindings/cardinality and test missing/ambiguous rejection.
5. **DirectKind control:** run existing positive/negative direct tests unchanged; assert its current index/topology acceptance/rejection and Cloth behavior are stable.

## SOL review and remaining review gate

SOL reviewed the finalizer, RED evidence, `PRODUCT_SPEC.md` lines 30–37, bounded acceptance lines 113–115, and this corrected design. SOL agreed full source-vertex lineage is not logically required to assign the whole imported final Mesh and is not required by the approved product contract. Lineage is only needed when promising to migrate or compare source-indexed state (for example Cloth/custom vertex buffers, source blendshape deltas, or source-to-final corner/face semantic continuity). Those states are rejected or explicitly outside this zero-shape/component-limited scope. The current RED's geometry-equality result remains a test oracle for that fixture and is not a general finalizer policy.

No product source or test code changed. Existing implementation guards remain until the new safety tests are authored and verified RED. The next code step is to add the regression tests above, observe their expected failures, then implement only the limited whole-final-Mesh replacement contract. This design does not claim a GREEN result or general topology-edit support.
